# Протокол розмітки — вимір власного відбору

> **Мета:** перевірити те, що бектестом перевірити не можна — **чи ваш відбір додає перевагу**.
> Механічний сетап дає **+1.3 пп** над монетою ([[ts32-lowrr-2026-09-16]], [[ts2-result-2026-09-16]]). Питання: скільки додає рішення «брати / не брати».

---

## 🔴 Правило №1: ви НЕ заповнюєте результат

У таблиці **немає** колонок `результат`, `R`, `профіт`. Це навмисно.

Ви даєте: **час, напрямок, entry, SL, TP**.
Я рахую R сам із даних.

Якщо ви заповните результат — вибірка стане непридатною: рука несвідомо тягнеться відмічати ті сетапи, які спрацювали. Це не питання чесності, це як працює пам'ять.

## 🔴 Правило №2: skipped-сетапи обов'язкові

**Відбір вимірюється тільки в порівнянні.** Якщо записати лише взяті угоди — виміряється виконання, а не відбір.

Записуйте **кожен** сетап, який ви **побачили**, зокрема ті, від яких відмовились. Колонка `taken` = `no`, решта полів заповнюється так само: який був би entry, який SL, який TP.

Орієнтир: **skipped має бути не менше, ніж taken.** Якщо skipped мало — значить, ви або не фіксуєте відмови, або відбору фактично немає.

## 🔴 Правило №3: bar replay, не гортання назад

1. TradingView → Bar Replay → стати на **бар рішення**
2. Праву частину графіка **не відкривати**
3. Заповнити рядок
4. Тільки потім рухатись далі

Розмітка «по пам'яті» на відкритому графіку **не годиться** — це не вибірка, а переказ.

|---|---|

| Період | **2024-01-01 → 2026-08-25** |

> Хочете розмічати GBPUSD / XAU / вересень 2026 — скажіть, завантажу дані з Dukascopy. Це кілька годин на інструмент.

## Скільки треба — чесно

Тест: взяті сетапи проти **нульової моделі** (та сама геометрія, напрямок монетою).

| N взятих | Похибка | Побачимо ефект від |
|---|---|---|
| 20 | ±11 пп | **+31 пп** |
| 30 | ±9.1 пп | **+25 пп** |
| **40** | **±7.9 пп** | **+22 пп** |
| 67 | ±6.1 пп | **+17 пп** |
| 150 | ±4.1 пп | +11 пп |

**20–30 — це пілот, а не вердикт.** Він відповість лише на питання «чи є великий ефект». Робочий мінімум — **40**, надійний — **67**.

> Порівняння «taken проти skipped» потребувало б ~170 у кожній групі — це нереально. Тому skipped використовуються **описово**: чи справді пропущені гірші.

## Поля

| Колонка | Що писати | Обов'язково |
|---|---|---|
| `id` | порядковий номер | ✅ |
| `datetime_utc` | бар рішення, `YYYY-MM-DD HH:MM` **UTC**, кратно 15 хв | ✅ |
| `direction` | `long` / `short` | ✅ |
| `taken` | `yes` / `no` — брали чи відмовились | ✅ |
| `entry` | ціна входу (5 знаків) | ✅ |
| `entry_type` | `limit` / `market` | ✅ |
| `sl` | ціна стопа | ✅ |
| `tp` | ціна цілі | ✅ |
| `conviction` | 1–5, наскільки впевнені **на момент рішення** | ✅ |
| `narrative_b` | куди очікуєте: `W1 Fractal High 1.1020` | ✅ |
| `why` | макро-теза або `null` | |
| `market_state` | `expansion` / `compression` / `overextension` | |
| `model` | `VC` / `IDM` / `market` / `other` | |
| `skip_reason` | якщо `taken=no` — чому відмовились | лише для no |
| `notes` | будь-що | |

**`conviction` і `taken` — головні колонки.** Саме на них перевіряється відбір: якщо ваші «5 з 5» систематично кращі за «2 з 5», відбір працює.

---

## Що я порахую

1. **Взяті проти нуля** — основний тест. WR, E, надлишок з CI.
2. **Conviction-градієнт** — чи 4–5 кращі за 1–2. Це найчутливіший тест відбору: він використовує всю вибірку, а не половину.
3. **Пропущені** — чи справді гірші за взяті.
4. **Розклад** по `why` / `market_state` / `model` — описово, з поправкою на множинність.
5. **MDE** для фактичного N — щоб одразу було видно, що саме вибірка може довести.
