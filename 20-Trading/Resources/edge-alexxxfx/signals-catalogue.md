## 1. Сетапи входу — 4 моделі

Джерело: `Entry Models by THE EDGE` (62 с.), `Entry Model INDUCED RTO` (24 с.).

| # | Модель | Умова | Вхід | SL |
|---|---|---|---|---|
| **M1** | **Volume Confirmation** | після реакції на KL сформувався чистий `X-1 TF VC` (RB / SNR / FVG) | за VC-елементом | за VC / Strong H-L |
| **M2** | **IDM — Induced RTO** | Fractal H/L усередині або біля POI | лімітом у зоні IDM | **за Strong High / Low** |
| **M3** | **Market** | ідея підтверджена, тесту не буде | по ринку | за відміну ідеї |
| **M4** | **Position Adding** | `X TF Storyline` живий + новий `X-1 TF KL` | на новому KL | за нові Strong H/L |

**Методологія M2 — 4 варіанти ланцюга:**

```
1. X TF POI → X-1 TF Trigger → X-1 TF VC → X-2 TF IDM Execution
2. X TF POI [LIQ] → X-1 TF VC → X-2 TF IDM Execution
3. X TF POI → X-1 TF VC → X-2 TF IDM Execution
4. X TF Trigger → X TF VC = IDM Execution
```

**Чому моделей чотири.** Математика автора: 20 днів → у 10 правильний Bias. Якщо торгуєш **лише FVG-входи**, з тих 10 реалізуються **2**. Решта 8 — «напрямок вгадав, входу не було».

> 📊 Виміряно нами: лімітний вхід M2 **не наповнюється в 24% випадків** (AB, свінг) і в **88%** (ТС-3, інтрадей). Тобто «гарантований вхід», заявлений як перевага M2, гарантований не завжди.

## 2. Сигнали **сили** — підстава торгувати продовження

| # | Сигнал | Що означає |
|---|---|---|
| 2.1 | Ціна реагує на **найближчу** неефективність і продовжує рух | Strong Order Flow — первинний індикатор сили тренду |
| 2.2 | Ціна дійшла до Strong High [OB], отримала rejection — **і все одно пішла далі** від найближчої неефективності | strong OF; зустрічний обсяг не втримав |
| 2.3 | Ціна **заповнює** зустрічний FVG по ходу руху | ознака сили: неефективність не зупиняє |
| 2.4 | OF не змінився попри досягнення **main TA** | «OF валідний, поки не доведено протилежне» |
| 2.5 | HH сформовано на **Raid ліквідності**, а не на trendline liquidity | рух істинний, а не інженерний |
| 2.6 | Fractal High/Low усередині POI у бік тренду | Continuation Trigger — продовження через його зняття |

## 3. Сигнали **слабкості** — підстава чекати розвороту

| # | Сигнал | Що означає |
|---|---|---|
| 3.1 | Закриття **тілом усередині** FVG з мінімальним rejection | зона слабка → підвищена ймовірність повного пробиття |
| 3.2 | Реакція на значиму TA **слабка** | ймовірність продовження в бік TA низька |
| 3.3 | Ціна **не змогла** продовжити рух після тесту ключової зони | ймовірність глибшої корекції висока |
| 3.4 | Доставка до зони через **Trendline Liquidity** | прямий індикатор слабкості руху |
| 3.5 | Консолідація + counter-liquidity zone після HTF Fractal Raid | висока ймовірність руху **проти** Raid |
| 3.6 | Бічне сповільнення в Discount актуального Dealing Range | виснаження продажів → ймовірність реверсу |
| 3.7 | Немає реакції на `main IPA` навіть корекційної | слабкість наміру |

## 4. Умови **пропуску** — коли не входити

| # | Умова | Чому |
|---|---|---|
| **4.1** | Сетап сформований **прямо під/над EQH / EQL** | низька ймовірність відпрацювання |
| **4.2** | Позиція по OF з ціллю EQL/EQH, але **над/під позицією є неефективність** | з більшою ймовірністю вийдеш по стопу |
| **4.3** | Над/під FVG є **OB або Fractal Point** | ймовірність тесту FVG **зменшується** |
| 4.4 | Ціна в діапазоні без main trigger | low-probability environment |
| 4.5 | Глибока корекція всередину POI після тесту | знижує ймовірність продовження |
| 4.6 | `Raid ≠ Reversal` — зняття рівня без зміни OF | напрямок не змінився |

> **4.1–4.3 — найконкретніші правила в усьому корпусі.** Вони формулюються як механічні умови і **піддаються перевірці**. Рекомендую перевірити першими.

## 5. Логіка **цілей**

| # | Правило |
|---|---|
| 5.1 | Ціна **не знімає EQH / EQL одразу** — спершу робить pullback за trendline liquidity |
| 5.2 | Після досягнення Key TA ціна робить **retracement** для пошуку Continuation Trigger (Fractal point / FVG) |
| 5.3 | Ціна знімає ключові рівні не одразу, а через retracement до найближчої неефективності / ліквідності / проторгованого обсягу |
| 5.4 | Якщо EQL/EQH сформовані або ціна розвернулась перед ними — шукати **Continuation trade** після зняття Fractal points у найближчій POI |
| 5.5 | Доставка у FVG **підвищує ймовірність пересвіпу** |
| 5.6 | Компресія → експансія; при High-Probability Target формація завершується експансією в протилежний бік |

## 7. Shift — робота з проблемною зоною

Найпрактичніший механізм каталогу. Вирішує проблему «FTA паралізує вхід».

```
Умови зміщення POI:  доставка у FTA/TA в рамках VC  +  RR ще прийнятний  +  Fractal H/L → RB
Дія:                 X-1 TF VC  стає новим  X TF Key Level
```

Три правила поведінки:
1. Розглядати FTA/TA як **звичайний KL**, незалежно від напрямку ринку.
2. SL ставити за **повну відміну ідеї**, а не за локальну проблемну зону.
3. Спиратись на **актуальний Narrative**, а не на локальні TA.

## 9. Що перевіряти далі — за пріоритетом

Відібрано за критерієм «механічно формалізується + часто трапляється».

| # | Правило | Чому перше |
|---|---|---|
| 1 | **4.3** — наявність OB/Fractal над FVG зменшує ймовірність його тесту | повністю механічне, легко порахувати частоту тесту з фільтром і без |
| 2 | **4.1** — сетап під EQH/EQL має низьку ймовірність | EQH/EQL формалізуються; це прямий фільтр входу |
| 3 | **5.1** — EQH/EQL не знімаються одразу, спершу pullback | бінарна подія, накопичується швидко |
| 4 | **3.1** — закриття тілом у FVG → підвищена ймовірність пробиття | механічне, дає прогноз наступного бара |
| 5 | **2.1** — Strong OF як індикатор продовження | вже частково закладено в детектори |

> Кожне з цих п'яти — **бінарна подія**, а не R-результат. Тому вони перевіряються на сотнях спостережень за місяці, а не на десятках трейдів за роки. Це той самий урок потужності, що й у [[mde-ts-program-2026-09-16]].
