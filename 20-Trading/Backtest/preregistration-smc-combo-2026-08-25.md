> змінюється. Заборонено: перебір сітки, вибір «найкращого» вікна, ретроспективне
> послаблення фільтра (A14 + правило множинних перевірок з `RULES.md`).

## 2. Зафіксовані параметри

Позначення: **[Н]** — число взяте прямо з нотатки стратегії; **[П]** — стандартне
значення, вже вживане в цьому проєкті (не винайдене тут); **[В]** — вигадане,
призначається один раз.

### Пункт 1 — HTF bias

| Параметр | Значення | Обґрунтування |
|---|---|---|
| Носій bias | **H4**, побудований з H1-барів | Нотатка називає три ТФ (W/D/H4). H4 — єдиний, який покривається наявними даними (найдовше вікно = 8 міс). W/D дали б 1–2 незалежні спостереження за вікно. **[В]** |
| Функція | `s88/common.py::h4_trend_at` без змін | **[П]** — вже написана й використана в проєкті, не переписується під цю задачу |
| `n_h4` (глибина структури) | **3 блоки** | Мінімальне прочитання «структура HH/HL» (множина): ≥2 послідовні вищі хаї і ≥2 вищі лоу → 3 блоки. Дефолт s88 (`n_h4=6`) вимагає 6 монотонних блоків поспіль — за конструкцією дає майже нуль подій. **[В]** |
| Умова | `h4_trend == "up"` для LONG, `"down"` для SHORT | пряме прочитання **[Н]** |
| «Discount / premium зона» | **ВІДКИНУТО** | Не формалізовна без 3 додаткових СС (від якого свінгу міряти Fib, який поріг). Відкидання **послаблює** фільтр → більше подій → більше потужності. Напрямок зміщення названий явно. **[В]** |

### Пункт 2 — OB confluence H4 + H1

| Параметр | Значення | Обґрунтування |
|---|---|---|
| Bullish (demand) OB | остання ведмежа свічка (`close < open`) перед імпульсом угору | пряме прочитання **[Н]** |
| «Сильний рух» = імпульс | максимум наступних **3** барів вище OB-high на **≥ 1.0 × ATR14** цього ТФ | ATR-нормування — щоб поріг не залежав від режиму волатильності. `3` бари й `1.0×` — круглі дефолти, сітка не перебиралась. **[В][В]** |
| Межі зони | **повний бар** `[low, high]` | Найпоширеніша конвенція; альтернатива «тільки тіло» дає вужчу зону і менше подій. **[В]** |
| Макс. вік OB | **30 барів** свого ТФ | H1: 30 год ≈ 1.5 доби; H4: 5 діб. Круглий дефолт. **[В]** |
| Мітигація | OB згорає, коли бар **закривається** за протилежним краєм зони | Найм'якше з поширених правил (дозволяє повторні тести). **[В]** |
| Confluence | зони H4 та H1 **перетинаються** (будь-яке перекриття > 0) | Пряме прочитання «перетин двох ТФ» **[Н]**; поріг «≥X% перекриття» не вводиться |
| POI-зона для подальших кроків | **перетин** H4∩H1 | «confluence = перетин» **[Н]** |
| Гілка «H1 OB + M15 FVG overlap» | **ВІДКИНУТО** | Друга рівноправна гілка з власним набором параметрів FVG. Тестування обох = дві гіпотези. **[В]** |

### Пункт 3 — sweep

| Параметр | Значення | Обґрунтування |
|---|---|---|
| Референс ліквідності | **нижній край POI-зони** (LONG) / верхній (SHORT) | Перший варіант у нотатці; «локальний HL» — альтернативна гілка, не тестується **[Н]** |
| Умова | `low < zone_low` (LONG), `high > zone_high` (SHORT) | пряме **[Н]** |
| Макс. глибина sweep | **15 пунктів** | Верхня межа діапазону, названого нотаткою («5-15 pips нижче зони») **[Н]** |
| Вікна (KZ) | London **07:00–09:00 UTC**, NY **12:00–14:00 UTC** | Таблиця сесій самої нотатки **[Н]**. DST не застосовується — беруться числа спеки як є |

### Пункт 4 — rejection candle

| Параметр | Значення | Обґрунтування |
|---|---|---|
| Вікно пошуку | sweep-бар або наступні **3** бари | «після sweep» без числа; 3 — круглий дефолт **[В]** |
| Умова закриття | `close > zone_high` (LONG) | «закривається ВИЩЕ зони» **[Н]** |
| «Велике тіло» | `|close−open| ≥ 0.5 × (high−low)` | Мінімальне прочитання «велике тіло» = тіло переважає тінь **[В]** |
| «Обсяг вищий за середній» | `volume > mean(volume останніх 20 M15-барів)` | «вищий за середній» = множник рівно **1.0** (не 1.5, не 2.0 — це вже підбір). Lookback 20 — круглий дефолт **[Н]** для множника, **[В]** для lookback |
| ⚠️ Застереження | обсяг у FX = тік-волюм фіда, не реальний | зафіксовано в аудиті; результат по цьому фільтру не переноситься на інший фід |

### Пункт 5 — retest entry

| Параметр | Значення | Обґрунтування |
|---|---|---|
| Вікно | наступні **1–2** бари після rejection | **[Н]** |
| «Рівень відбою» | `zone_high` (LONG) / `zone_low` (SHORT) | Найоднозначніший з трьох кандидатів (верх OB / close rejection / open rejection) **[В]** |
| Умова retest | `low ≤ zone_high` **І** `close > zone_high` **І** `low > sweep_low` | «повертаються до рівня, але не нижче sweep low, закриваються вище» **[Н]**. Допуск у пунктах **не вводиться** (0 СС) |
| Гілка «double test» | **ВІДКИНУТО** | Окреме правило з власними параметрами **[В]** |
| Сигнальний бар | retest-бар; **fill = open наступного бару** | конвенція харнесу, без look-ahead **[П]** |

### Геометрія

| Параметр | Значення | Обґрунтування |
|---|---|---|
| SL | `sweep_low − 7 п` (LONG) / `sweep_high + 7 п` (SHORT) | Приклад нотатки: «буфер ~7 pips», діапазон 5–10 **[Н]** |
| `sl_pips` | `|fill_open − SL|`, **індивідуально на угоду** | правило дає відстань, а не константу |
| Мінімальний SL | **5 п** | нижче — стоп усередині спреду+шуму, неторговельно. Кількість зачеплених угод звітується окремо **[В]** |
| TP | **3.0 × sl_pips** (брутто) | «Min RR 1:3» — єдине число для цілі в нотатці **[Н]**. Альтернатива «найближчий H1 Supply OB» додала б 7 СС |
| Часткова фіксація TP1/runner, BE | **ВІДКИНУТО** — один вихід | розміри часток не задані жодним числом **[В]** |
| Витрати `c` | **2.0 п**, симетрично | `RULES.md` A10, чинна константа проєкту **[П]** |
| Flat | **19:00 UTC** | `session-windows.md`, чинне значення **[П]** |
| Одна угода на день | **ні** — кожна KZ незалежно, макс. 1 сигнал на KZ | Нотатка описує два незалежні пріоритетні вікна **[Н]** |

## 3. Нульова модель (A7)

Дві незалежні побудови, обидві обов'язкові:

1. **Matched null** — для кожної реальної угоди `K = 30` випадкових входів на
   допустимих барах **того самого вікна** (будні, ті самі KZ-години), випадковий
   напрямок, **та сама `sl_pips` і той самий `tp_r_mult`**. Це головна база
   порівняння.
2. **Exhaustive null із медіанною геометрією** — для перевірки закону A10
   `E_нуля ≈ −c/(SL+c)`.

Плацебо-зсув: `+1, +3, +8` барів (конвенція `entry_v2.py`).
Bootstrap: 5000 ітерацій, ресемпл обох вибірок, α = 0.05.

## 5. Критерій успіху — зафіксований до прогону

Стратегія вважається такою, що **пройшла**, лише якщо виконано **всі чотири**:

| # | Умова | Поріг |
|---|---|---|
| **C1** | Надлишок над matched-нулем на **DEV** | `≥ +0.15R`, 95% CI **не містить нуля** |
| **C2** | Знак надлишку тримається на **CHECKPOINT** | `> 0` |
| **C3** | **A16** — середній надлишок у пунктах на угоду | `≥ 10 п` |
| **C4** | **A8** — медіанна угода | `> 0` (едж не в хвості) |

Будь-яке невиконання → **не пройшла**. Часткові успіхи не інтерпретуються як
«перспективно» — при 21 вигаданому параметрі часткові успіхи очікувані від шуму.

## 6. Робастність (A9) — оголошено заздалегідь

Прогін повторюється при `n_h4 ∈ {2, 3, 4}`. **Вердикт виноситься за `n_h4 = 3`**
(основне значення). Решта — лише перевірка «чи не перевертається знак».
Вибір найкращого з трьох **заборонений** і не буде зроблений.

## 7. Заздалегідь оголошений запасний прогін (питання потужності)

Патерн рідкісний. Якщо `n < 5` (`MIN_TRADES_HARD`) у вікні — додатково
виконується **вторинний** прогін з розширеним часовим вікном
**07:00–16:00 UTC** (London + NY повністю, за таблицею сесій нотатки).
Він **не може** дати «пройшла» — оголошується тут лише щоб отримати оцінку
частоти подій і `MDE`, і буде помічений як вторинний.
