# ADR-2026-08-06 — Kanboard як трекер задач для агентів

**Status:** accepted
**Date:** 2026-08-06

## Контекст

Потрібні канбан-дошки, куди агенти самі заводять задачі, рухають їх по статусах і пишуть, що зроблено та що лишилось. Дошки мають бути доступні з будь-якої сесії, але кожен агент працює зі своїм проектом.

Рішення ухвалювалось у три заходи, і кожен раз нове обмеження перекидало вибір:

1. **Спочатку** розглядались Vikunja / Planka / Obsidian Kanban / Dataview. Вибір упав на Planka — за Trello-подібний UI.
2. **Потім** з'ясувалось, що сервер — VPS під **Webuzo**, і контейнери ставити не хочемо. Planka без Docker означає збірку Node.js з вихідників — відпала. Kanboard натомість є в Softaculous, тобто ставиться кнопкою з панелі.
3. **Далі** вирішили почати локально, а не на VPS. Обрали Vikunja, але виявилось, що на машині вже стоїть **Laravel Valet** із PHP 8.2 — а Vikunja написана на Go, і Valet їй нічим не допомагає.

Валідна на момент рішення обстановка на Mac: Valet 4.6.1, TLD `.loc`, PHP 8.2.19 з усіма 13 потрібними розширеннями, nginx і php-fpm уже запущені, ~40 сайтів на `.loc`.

## Рішення

**Kanboard 1.2.53 локально через Valet** на `http://tasks.loc`, база — SQLite. MCP-сервер `bivex/kanboard-mcp` (Go) працює локально й ходить до Kanboard по JSON-RPC. Зареєстрований глобально, тому доступний у кожній сесії.

Ізоляція по проектах **свідомо відкладена** — межу поки тримає правило в `~/.claude/CLAUDE.md`.

## Альтернативи (відкинуті)

| Варіант | Чому відкинули |
|---------|----------------|
| Planka | Без Docker — збірка Node.js з вихідників, на Webuzo це постійний біль. Готових архівів немає |
| Vikunja | Go-бінарник, потребує окремого демона через launchd. Valet її не обслуговує, дав би лише проксі |
| Obsidian Kanban | Паралельні агенти затирають правки одне одного в одному markdown-файлі. Немає API |
| Dataview | Тільки таблиці, без drag&drop. Статус міняється правкою frontmatter |
| SQLite + власний MCP | ~день роботи, коли готові MCP вже існують |

## Наслідки

**Позитивні:**
- Нуль нових процесів, портів і демонів на Mac — працює через уже запущені nginx + php-fpm
- Той самий стек, що й на Webuzo → перенесення на VPS буде копією папки та бази, а не міграцією технології
- Три готові MCP-сервери на вибір; узятий дає 171 інструмент
- Оновлення Kanboard на VPS потім — кнопкою в панелі

**Негативні / трейдофи:**
- UI помітно скромніший за Trello/Planka — це усвідомлена плата за простоту встановлення
- Ізоляції по проектах немає: агент бачить усі 16 дощок, і промах проектом технічно можливий
- `bivex/kanboard-mcp` молодий, з малою кількістю комітів. Запасний варіант — `hoducha/kanboard-mcp` (Python)

**Що це unlocks:**
- Перенесення на Webuzo без зміни стека
- Ізоляція через окремий API-токен на проект — робиться в адмінці, коду не потребує
- `bivex` підтримує RBAC (`KANBOARD_USER_PROJECT_ROLES`) — можливий другий шар обмежень

## Перегляд

Переглянути, коли: (а) агенти почнуть регулярно промахуватись проектом — вмикати токени на проект; (б) UI почне заважати — тоді Planka на VPS у Docker; (в) `bivex/kanboard-mcp` виявиться нестабільним — перемикатись на `hoducha`.
