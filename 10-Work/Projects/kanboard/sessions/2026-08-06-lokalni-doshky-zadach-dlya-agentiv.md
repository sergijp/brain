# kanboard — локальні дошки задач для агентів

## Мета сесії

Зробити канбан-дошки, куди агенти самі заводять задачі, рухають їх по статусах і пишуть, що зробили та що лишилось. Дошки мають бути видні з будь-якої сесії, кожен агент — у свій проект.

## Виконано

| Задача | Результат |
|---|---|
| Огляд варіантів | 4 підходи з візуальним мокапом-порівнянням |
| Установка трекера | Kanboard 1.2.53 у `~/Data/Source/kanboard`, SQLite |
| Підключення до Valet | `valet link tasks` → http://tasks.loc, HTTP 302 на логін |
| Увімкнення API | `config.php` із `API_AUTHENTICATION_TOKEN`, JSON-RPC відповідає |
| Дошки під проекти | 16 проектів, колонки Backlog / In progress / Review / Done |
| MCP-сервер | `bivex/kanboard-mcp` зібрано з Go, 171 інструмент, `✔ Connected` |
| Реєстрація MCP | Глобально через `claude mcp add --scope user` |
| Правило поведінки | Секція «Дошки задач» у `~/.claude/CLAUDE.md` |

Дошки заведено під проекти з реальною історією сесій: `3g`, `mono-system`, `trading`, `onchul`, `BET`, `maria`, `travy`, `buktrek`, `air-trans`, `bustrek`, `tradingview-mcp`, `dashboard`, `trading-telegram-bot`, `visson-ecosystem`, `skills`, `api-setup`.

## Важливі рішення

Коротко: рішення перекидалось тричі. Planka → відпала, бо на Webuzo без Docker це збірка Node з вихідників. Vikunja → відпала, бо Valet обслуговує PHP, а вона на Go. Kanboard виграв, бо рідний для наявного оточення і на VPS ляже тим самим стеком.

## Проблеми й як вирішили

**Kanboard більше не публікує готові архіви.** У GitHub-релізі `v1.2.53` нуль assets — тільки source. Перевірка показала, що `vendor/` закомічений у репозиторій (358 записів), тож `composer install` не потрібен — архів тегу ставиться як є.

**Хибний діагноз MCP-сервера.** Перший тест через `printf | binary` показав, що `initialize` відповідає, а `tools/call` мовчить. Причина була не в сервері, а в тесті: процес завершувався, щойно закривався stdin, не дочекавшись HTTP-відповіді від Kanboard. З утриманим stdin усе працює — `get_all_projects` повертає всі 16 дощок.

**Valet і .htaccess.** Kanboard постачається з `.htaccess` для Apache, а Valet працює на nginx. Вирішено через `ENABLE_URL_REWRITE = false` — Kanboard використовує `?controller=...` URL-и й без rewrite.

**Тема Nebula несумісна з 1.2.53.** Ставили її як готове рішення для вигляду — вона видала PHP-warning просто на сторінці. Її `Template/layout.php` вантажить `assets/css/app.min.css`, якого в 1.2.53 вже немає: файл розділили на `light.min.css` / `dark.min.css` / `auto.min.css`. Плагін відстав від Kanboard. Видалено; замість неї — вбудована тема плюс власний CSS-плагін `Refined`.

**Дашборд був порожній.** Задачі не потрапляли в «My tasks», бо створювались без `owner_id`. Глибша причина — `admin` не був учасником жодного проекту: проекти заводились через API під службовим `jsonrpc`, а Kanboard не дає призначити задачу на нечлена проекту. `updateTask` мовчки повертав `false`. Вирішено `addProjectUser` для всіх 17 проектів + правило в CLAUDE.md призначати нові таски на `owner_id: 1`.

**Сесія кешує тему й мову.** Зміна `users.theme` та `users.language` прямо в SQLite не діє до наступного входу — Kanboard читає їх із сесії (`$this->user->getTheme()`, `session_get('user')['language']`). `APPLICATION_LANGUAGE` у `config.php` при цьому перекривається порожнім значенням у профілі. Вирішено: `UPDATE users` + `DELETE FROM sessions`.

**Модалка розтягувалась на весь екран.** У `#modal-box` немає `max-width`, а JS виставляє інлайном `width: 1350px`. Форма з вузькими полями розповзалась порожнечею. Обмежено до 620px, а для форм задачі — 1080px через `#modal-box:has(.task-form-container)`.

**Три колонки форми задачі зривались униз.** Головна колонка 60% плюс дві по 20%, але з `min-width: 200px`: при контейнері 956px сума виходила 973px і третя колонка переносилась. Вирішено ширшою модалкою плюс `main-column: 55%` усередині модалки.

**Власні CSS-правила конфліктували між собою.** Поле оцінки часу лишалось 160px попри пізніше правило зі 105px — старіший селектор `#modal-content form input.form-numeric` (1,2,1) перебивав новий `.task-form-secondary-column .form-numeric` (0,2,0). Через це слово «годин» не вміщалось поруч і падало на наступний рядок. Урок: у цьому CSS специфічність важливіша за порядок.

**Kanboard не позначає активну тему в DOM.** Ні класу на `<body>`, ні data-атрибута — тему видно лише з того, який файл підключено (`light.min.css` чи `dark.min.css`). Тому CSS сам відрізнити тему не може. Вирішено з боку PHP: `Plugin.php` читає `$this->userSession->getTheme()` і підключає `refined-light.css`, `refined-dark.css` або `refined-auto.css` (останній — через `@media (prefers-color-scheme)`). `refined.css` описує лише структуру через змінні `--refined-*`, конкретні значення приходять із файлу палітри.

Дублювання значень між трьома тематичними файлами усунуто: усі кольори винесено в `refined-palette.css` як два набори (`--rl-*` світлий, `--rd-*` темний), а тематичні файли стали тонкими мапінгами `--refined-* → --rl-*/--rd-*` і власних значень не містять. Колір правиться в одному місці.

**Кольорові заливки ламали темну тему.** `.task-summary-container.color-green` заливається пастельним зеленим із жорстким `color: rgb(0,0,0)` — на темному фоні текст тонув. Замінено на нейтральну підкладку з кольоровою смугою зліва плюс повернуто колір теми тексту.

## Артефакти

- `~/Data/Source/kanboard/` — Kanboard 1.2.53
- `~/Data/Source/kanboard/config.php` — SQLite, API-токен, `ENABLE_URL_REWRITE=false`, timezone Europe/Kyiv
- `~/Data/Source/kanboard/data/db.sqlite` — база (396 КБ)
- `~/Data/Source/kanboard-mcp/` — репозиторій + зібраний бінарник (7.5 МБ)
- `~/Data/Source/kanboard/plugins/Refined/` — власний CSS-плагін v1.1.0. Покриває дошку, модалки, форми, сторінку задачі, список, дашборд, бічні меню, fieldset-групи
  - `refined.css` — структура: розміри, відступи, типографіка. Кольори бере зі змінних `--refined-*` та рідних змінних Kanboard
  - `refined-palette.css` — **єдине джерело кольорів**. Два набори: `--rl-*` (світлий) і `--rd-*` (темний)
  - `refined-light.css` / `refined-dark.css` / `refined-auto.css` — тонкі мапінги без власних значень. Світла тема дзеркальна до темної: там картка світліша за тло, тут тло сіре (`#eceff5`), а картка біла з тінню. Логіка глибини та сама, полюси протилежні
  - Нейтралі мають холодний синій ухил, а не чистий сірий — інакше інтерфейс читається вицвілим
  - Колонки дошки позначені кольором за змістом: очікує (сірий) → в роботі (бурштин) → на перевірці (синій) → готово (зелений). Прив'язка по позиції через `:nth-child`, бо CSS не знає назв колонок; розраховано на звичний набір із чотирьох
  - Покриття компонентів рахувалось скриптом: із 384 класів Kanboard стилізовано 95 (решта — кольорові літерали й дрібні утиліти). Покрито аватари, підказки, перемикач вигляду, поля з приставкою, підзадачі, стрічку подій, markdown, файли, кастомні селекти, drag&drop, панелі налаштувань, сторінку входу, редактор тексту, пагінацію

### Система токенів (осучаснення)

Корінь «застарілого» вигляду Kanboard — не кольори, а фундамент: шрифт **Helvetica Neue**, розміри в хаотичних `em` (.7 / .8 / .85 / .9 / 1.2 / 1.4) без шкали, три різні радіуси (3 / 4 / 5px), одношарові тіні. Замість точкових правок заведено систему в `:root` файлу `refined.css`:

| Токен | Призначення |
|---|---|
| `--rf-font` | системний стек (SF Pro на macOS, Segoe UI на Windows) — найбільший одномоментний зсув |
| `--rf-text-xs…xl` | типографічна шкала з шести фіксованих розмірів |
| `--rf-space-1…6` | крок відступів, кратність 4 |
| `--rf-radius-sm/base/lg` | три радіуси замість трьох випадкових |
| `--rf-ease` | єдина крива переходів |

Скриптом переведено на токени 98 місць: 38 радіусів, 52 розміри шрифту, 8 переходів. Тіні зроблено багатошаровими — одношарова завжди читається як накладка, а не як глибина.

### Акцент — зелений

Палітру переведено з синьої на зелену однією правкою в `refined-palette.css` (саме заради цього кольори й виносились в одне місце). Щоб синього не лишилось узагалі, перевизначено й рідні змінні Kanboard: `--link-color-primary`, `--button-primary-*`. Статус «на перевірці» змінено з синього на фіолетовий — інакше він конфліктував би з зеленим акцентом.

### Структурні зміни інтерфейсу

- **Список проєктів → сітка карток.** Рядок проєкту відрізняється від рядка задачі класом `.table-border-left`, тому `.table-list:has(.table-list-row.table-border-left)` дозволяє перебудувати саме контейнер проєктів у grid, не зачепивши списки задач. Лічильники по колонках розфарбовані тим самим кодом, що й смуги над колонками дошки.
- **Секції задачі → картки.** `details.accordion-section` отримали фон, рамку, власний маркер розгортання замість системного трикутника; розгорнута секція позначається акцентною смугою.
- **Бічне меню.** Kanboard задає `.sidebar > ul a { color: var(--color-light) }` зі специфічністю (0,2,1) — через це текст лишався світло-сірим `#777` попри наше правило. Довелось підняти специфічність. Активний пункт малювався двічі: чорна рамка Kanboard плюс наша акцентна — прибрано чорну.

**Одруківка в CSS самого Kanboard.** `.views a` посилається на `var(--color-ligth)` — такої змінної немає (правильно `--color-light`), тому колір падав на дефолт браузера. Задано явно в `refined.css`.

**`.dropdown-menu` у Kanboard — це ТРИГЕР, а не меню.** Саме випадне меню — `.dropdown-submenu-open`. Через хибне припущення рамка й тінь лягли на посилання-тригери, і номери задач (`#12`) перетворились на подобу кнопок. Виправлено: тригер із підписом стилізується як кнопка, номер задачі — як тихий підпис, меню — окремо.

**Календаря і Gantt у ядрі Kanboard 1.2.53 немає.** Серед 90 контролерів лише `ICalendarController` (експорт у iCal). Обидва винесені в окремі плагіни, які не встановлені. Аналітика в ядрі є — `AnalyticController` з методами `taskDistribution`, `cfd`, `burndown`, `leadAndCycleTime` тощо.
- Мова інтерфейсу — українська (`uk_UA`, переклад 1468 із 1472 рядків), часовий пояс `Europe/Kyiv`, тема `dark`
- `~/.claude/CLAUDE.md` — секція «Дошки задач — Kanboard (MCP `kanboard`)»
- `~/.claude.json` — MCP-сервер `kanboard` у user-scope

Ключові команди:

```bash
valet link tasks                                    # у папці kanboard
claude mcp add --scope user kanboard -e ... -- <бінарник>
curl -u "jsonrpc:<token>" -d '{"jsonrpc":"2.0","method":"getVersion","id":1}' \
     http://tasks.loc/jsonrpc.php
```

## Перехід на Trello

Наприкінці сесії трекер змінено на **Trello** — вирішальним аргументом став дизайн: у Kanboard на нього пішло ~1500 рядків власного CSS, у Trello він сучасний із коробки. Плюс офіційний MCP від Atlassian проти community-плагіна.

**Що з'ясувалось про офіційний сервер** (`https://mcp.trello.com/v1`, OAuth 2.0):

- **Одна робоча область на з'єднання.** Після першої авторизації MCP бачив лише `VissOn` — ні `Personal`, ні `Bustick`. Довелось переавторизуватись і явно обрати `Personal`. Побічний ефект корисний: агент фізично не дотягнеться до чужих дощок, тобто ізоляція, відкладена в Kanboard, тут виходить сама.
- **Немає інструменту для коментарів.** Стан задачі ведеться в `desc` картки (до 2048 символів). `action: "update"` перезаписує опис повністю, тому перед оновленням треба читати поточний і дописувати.
- Видалення не підтримується — лише архівування.

**Ліміти Free**, перевірені в документації: 10 **відкритих** дощок на робочу область; архівовані не рахуються. При 5-7 активних проектах цього вистачає з запасом, а проекти на паузі архівуються й звільняють слот. Мітки — 950 на дошку, картки — 5000; схема «одна дошка, проект = мітка» не знадобилась.

**Заведено в `Personal`:** `3G`, `Mono`, `Buktrek`, `Bustrek`, `Onchul` — по чотири колонки Backlog / In progress / Review / Done.

**Правило в `~/.claude/CLAUDE.md` переписано з Kanboard на Trello** (бекап — `CLAUDE.md.bak-20260806-1612`). Kanboard лишається робочим на `tasks.loc`, але агенти в нього більше не пишуть.

> **Урок про автоматизацію через UI.** Спроба створити дошки кліками в браузері провалилась тричі: діалог Trello перебудовує розмітку після введення назви, кнопки зсуваються, клік потрапляє в «Створити з шаблона». Через MCP ті самі 5 дощок і 20 колонок створились двома викликами без жодної помилки.
