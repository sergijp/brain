# screenbridge — архітектура відеопайплайну

**Код:** `~/Data/Source/screenbridge/`
**Мета:** MacBook Pro M1 (host) віддає екран на iMac 27" 2017 (client).

## Загальна схема

```
MacBook (host)                                iMac (client)
──────────────────                            ──────────────────
CGVirtualDisplay (приватний API)
        ↓
ScreenCaptureKit  (NV12, без конвертації)
        ↓
VideoToolbox H.264 (low-latency RC, без B-кадрів)
        ↓
Network.framework TCP + Bonjour  ────────→    Network.framework
                                                     ↓
CGEventPost       ←──── JSON-події ────────   AVSampleBufferDisplayLayer
```

## Форма постачання

Обидва застосунки — **menu bar агенти** (`LSUIElement`), без іконок у Dock.
Один універсальний DMG (`x86_64 arm64`) на обидві машини.

Обидва зберігають повноцінний CLI: **без аргументів — GUI, з аргументами —
термінал**. Це навмисно: діагностичні режими (`--test-pattern`, `--verify`,
`--stats`) не потребують дозволів і лишаються єдиним способом перевірити збірку
там, де Screen Recording не видано.

Налаштування живуть у `UserDefaults` — застосунок, запущений з Finder, не має
аргументів командного рядка.

## Таргети SPM

| Таргет | Роль |
|---|---|
| `CGVirtualDisplayShim` | ObjC-шим приватного API. Лише селектори, без лінк-залежності від приватних класів |
| `ScreenBridgeCore` | Протокол, фреймінг, `SampleBufferBuilder`, збереження розкладки дисплеїв |
| `ScreenBridgeHost` | `HostController` (пайплайн), `HostMenuBar` (UI), захоплення, кодек, сервер, ін'єкція вводу |
| `ScreenBridgeClient` | Мережа, рендер, menu bar, `GlobalHotKey`, headless-верифікатор |

## Формат на дроті

Кожне повідомлення: `[UInt8 type][UInt32 BE length][payload]`.

| type | Вміст |
|---|---|
| 1 `control` | JSON — рукостискання, події миші й клавіатури, запит keyframe |
| 2 `videoConfig` | SPS + PPS + розмір. Шлеться з **кожним** keyframe, щоб клієнт міг під'єднатись серед потоку |
| 3 `videoFrame` | прапорці + PTS + H.264 в AVCC (4-байтовий префікс довжини на NAL) |

Керуючий трафік — JSON свідомо: він крихітний і рідкий, а дебажити його руками
незрівнянно легше за бінарник. Відео лишається сирим бінарним.

## Ключові інваріанти

1. **Вхідне TCP-з'єднання — лише кандидат.** Активним клієнтом воно стає, коли
   надішле валідне повідомлення. Причина — Happy Eyeballs: одне `NWConnection`
   до Bonjour-ендпоінта відкриває кілька TCP-з'єднань одночасно (IPv4 проти
   IPv6) і кидає програшне. Без цього правила хост вбиває з'єднання, яким
   клієнт саме збирається користуватись.
   → див. [[10-Work/Projects/screenbridge/sessions/2026-09-07-screenbridge-mvp]]

2. **Кадри дропаються, а не чергуються.** Понад 4 незавершені `send` — і
   не-keyframe відкидається. Несвоєчасний кадр гірший за пропущений, а
   безмежна черга перетворює затинку Wi-Fi на постійний лаг.

3. **Розкладка дисплеїв зберігається до створення віртуального екрана.**
   Поява дисплея змушує macOS переузгодити конфігурацію і збиває скейл
   основного екрана. `DisplayArrangement.capture()` / `.restore()` в
   `ManagedVirtualDisplay`, спрацьовує і на Ctrl-C.

4. **Рендерер і верифікатор ділять `SampleBufferBuilder`.** Шлях, який
   тестується, — це той самий шлях, що виконується.

5. **Стан `NWListener` треба спостерігати.** Невдала прив'язка до порту приходить
   асинхронно через `stateUpdateHandler`, а не кидається з `start()`. Без цього
   хост рапортує «чекаю клієнта», не слухаючи нічого.

6. **Схований клієнт не декодує.** Кадри відкидаються до наступного keyframe,
   при поверненні надсилається `requestKeyframe` — інакше декодер малює сміття
   з дельта-кадрів без опорного.

7. **Глобальний хоткей — тільки Carbon.** `RegisterEventHotKey` не потребує
   дозволів; `NSEvent.addGlobalMonitorForEvents` вимагав би Accessibility на
   клієнті, де інших дозволів не потрібно взагалі.

## Публічні точки входу

```bash
# без аргументів — menu bar застосунок
ScreenBridgeHost --virtual [WxH] | --display <id> | --test-pattern
ScreenBridgeClient [--host <addr>] [--windowed] [--verify] [--stats]
```

Гарячі клавіші клієнта: **⌃⌘D** показати/сховати (глобально), **⌃⌘E** віддати
клавіатуру, **⌃⌘Q** вихід.

`--test-pattern` (хост) і `--verify` (клієнт) не потребують жодних дозволів —
вони розділяють проблему захоплення, кодека й мережі.

## Дозволи

| Машина | Дозвіл | Наслідок відсутності |
|---|---|---|
| MacBook | Screen Recording | хост не стартує |
| MacBook | Accessibility | картинка йде, ввід мовчки ігнорується |
| iMac | — | не потрібні |

## Стан перевірки (2026-09-07)

**Перевірено на Ventura 13.7.8 Intel:** віртуальний дисплей, відновлення
розкладки, H.264 low-latency, фреймінг, TCP, Bonjour, декодування
(402/402 кадри, 0 помилок).

Додатково перевірено: рендер (`layer rendering`, 60–62 fps намальовано),
показати/сховати (0 fps і вікна немає в схованому стані), `UIElement`-статус
обох застосунків, монтування DMG.

**Не перевірено:** ScreenCaptureKit, ін'єкція вводу, виконання на arm64,
фактичне натискання ⌃⌘D, реальна затримка.
