# Аудит profumo-site (стан коду на коміті 8a037b3)

## 🔴 Безпека / гроші
1. Приватний ключ LiqPay потрапляє в `data`, що віддається у браузер — `Api/Shop/CheckoutController::getLiqpayData`, `PaymentMethods/CardPayment::getPaymentView`. Можна підробити callback → «оплатити» замовлення. Після фіксу — ротація ключа.
2. `POST /api/check-order` видаляє будь-яке неоплачене замовлення за `order_id` без перевірки власника.
3. Тип оплати (card чи ні) береться з клієнтського `payment_method_type`, а не з `payment_methods` у БД.
4. Публічний `Route::any('test')` у `routes/api.php` — шле лист реєстрації member #14.
5. `PUT /api/cart/product/{id}/quantity` — будь-який CartProduct, будь-яка кількість (у т.ч. від'ємна).
6. Гостьове замовлення прив'язується до існуючого Member за phone OR email і пише адресу в чужий профіль (`CheckoutService::newOrder`).
7. Соц-логін зливає акаунт за email і змінює `auth_type` → власник більше не може увійти паролем.

## 🟠 Функціональні баги
- `OrderObserver::created` спрацьовує до додавання товарів → лист з порожнім замовленням; `updated()` дивиться на неіснуючий `status_id` і передає не ті аргументи.
- Залишок списується при створенні замовлення; при закритті LiqPay замовлення видаляється, залишок не повертається.
- `Order::addProduct`: ціна sub-product без конвертації валюти; списується залишок product, а не варіанта.
- `Member::associateCart` при логіні губить `sub_product_id`.
- Логін по телефону не працює (користувача шукають тільки по email).
- Відсутні класи → 500: `Notifications\CallMe`, `Notifications\Faq`, `Mail\SendResume`; `catch` повертає статус `$e->getCode()` (0).
- `PageController`: шаблони `vacation`, `service_centers` без view.
- `BrandController`: 500 якщо немає AttributeOption з назвою бренду; відгуки фільтруються по category.id = brand.id; `'!=', 'null'` як рядок.
- Фільтр ціни `price=0-N` → undefined index (array_filter прибирає 0).
- Пошук / сторінка товару / схожі товари не фільтрують `active`.
- Ціна в SQL (`final_price`, сортування/фільтр) ≠ ціна на екрані (accessor бере sub-product).
- `Controller::__construct`: опечатка `$setting` → `hot_products_count` ігнорується.
- `Profile/OrdersController::getOrder`: null → 500 замість 404.

## 🟡 Продуктивність
- Кожен не-ajax запит: settings (двічі), дерево категорій, бренди, меню, мови; `CheckUrl` вантажить усі редиректи. Без кешу.
- N+1: accessor `price` тягне subProducts на кожен товар; currency без eager load на головній.
- `/api/bootstrap` на кожній сторінці створює cart/wishlist/comparison для кожної сесії (боти) → таблиці ростуть.

## 🟡 Валідація / XSS
- Без валідації: reviews, product comment (mark), addresses, call-me/contact/faq; у personal data немає unique для email/phone.
- `{!! !!}`: `list-reviews` (коментар користувача), breadcrumbs, faq title, error-сторінки (exception message).

## Техборг
- `composer.lock` і `package-lock.json` у `.gitignore` → невідтворювані збірки; `diglactic/laravel-breadcrumbs: "*"`.
- Laravel 9 / PHP 8.0 — EOL.
- `env()` поза config (EXTERNAL_LINK, LIQPAY_*, NOVA_POSHTA_API_KEY) → зламається після `config:cache`.
- Catalog/BrandController майже дублікати; мертвий код comparsion.
- Тестів немає; локально немає php/composer/node.
