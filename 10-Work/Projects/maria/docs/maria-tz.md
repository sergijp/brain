# Марія — AI нічний диспетчер автобусних перевезень

## Контекст

**Марія** — AI-агент, нічний диспетчер міжнародних автобусних перевезень.
Відповідає на дзвінки та повідомлення клієнтів уночі, поки живі диспетчери
сплять. Мета — не втрачати нічні звернення, давати інформацію з реальних даних
(CRM), приймати заявки, фіксувати все для денної зміни.

Передача зміни — живою командою денного диспетчера: «приступаєш до зміни» /
«закінчуєш зміну». Для телефону зміна — це правило маршрутизації в Бінотел
(день → люди, ніч → Марія).

## Фінальний стек (зібрано)

| Шар | Рішення | Нотатки |
|-----|---------|---------|
| **Мозок (логіка/флоу)** | **n8n-хаб з першого дня** | канали = тонкі адаптери до одного webhook |
| **LLM-шар** | **OpenRouter** | gpt-4o-mini / Claude Haiku + авто-fallback (нічний сервіс!) |
| **Дані** | **Власна CRM через API** | least-privilege, тільки дозволені задачі |
| **Журнал звернень / передача зміни** | **Новий модуль у власній ERP** | хто/коли/що хотів/статус; вранці денний диспетчер працює звідси. (Chatwoot — відкинуто) |
| **Телефонія (фронт)** | **Бінотел** (віртуальна АТС) | твої номери вже там; роутинг день/ніч |
| **Голос (STT/LLM/TTS)** | **Vapi або Retell** | Бінотел вночі віддає дзвінок сюди по SIP |
| **STT / TTS** | Deepgram / ElevenLabs (UA-голос) | у складі Vapi/Retell |
| **Хостинг** | Hostinger VPS (8 GB) | self-host |

### Рішення по мозку (v2, фінальне): n8n-хаб з першого дня
- **n8n = єдиний мозок від MVP.** Воркфлоу готовий: `n8n/maria-hub-workflow.json`
  (AI Agent через OpenRouter + пам'ять по контакту + CRM-tools + лог + нічне вікно).
- **Канали = тонкі адаптери** до одного webhook: Telethon userbot (реальний Telegram),
  BSP webhook (WhatsApp Coexistence), Instagram Trigger, Vapi (телефон — свій цикл,
  але той самий промпт+tools).
- **Чому не Hermes:** його Telegram-gateway = Bot API (@бот), а не реальний акаунт —
  головна причина; плюс автономний learning-loop суперечить строгому скоупу.
  Hermes — експериментальний запас, не в основній схемі.
- **Botpress** — у запасі, якщо діалоги стануть по-справжньому розгалуженими.

## Канали

Принцип: **усе на РЕАЛЬНИХ акаунтах, куди клієнти вже пишуть.** «Нічна зміна» —
не переадресація, а програмне правило: Марія авто-відповідає лише вночі; вдень
акаунти обслуговують живі люди у своїх застосунках. Клієнт не помічає різниці.

| Канал | Реальний акаунт зберігається | Через що | Зміна день/ніч |
|-------|------------------------------|----------|----------------|
| 📞 Телефон | ✅ той самий номер | **Бінотел → Vapi/Retell** | правило часу в Бінотел (реальна переадресація) |
| Telegram | ✅ **реальний акаунт** (userbot) | Hermes + api_id/api_hash | правило в агенті (нічне вікно) |
| WhatsApp | ✅ **той самий номер** (Coexistence) | офіц. Cloud API + застосунок одночасно | вдень люди в застосунку, вночі Марія через API |
| Instagram | ✅ **той самий проф-акаунт** | офіц. Messaging API (через FB Page) | вдень застосунок, вночі API; ліміт 200 DM/год |
| Viber | ❌ реальний неможливий | тільки Bot API (€100/міс) | відкладено |

**⭐ WhatsApp Coexistence (з 03.2026):** той самий номер працює ОДНОЧАСНО в застосунку
і через API. Клієнти пишуть на звичний номер; вдень диспетчери відповідають у WhatsApp
Business застосунку, вночі — Марія через API. Історія зберігається, застосунок не
втрачається, бану немає (офіційний шлях). Потрібно: Meta-верифікація + BSP, що
підтримує onboarding номера з застосунку (Coexistence).

> **Голосові повідомлення** у месенджерах — не обробляються; **дзвінок у месенджері** —
> скидати + «зателефонуйте на робочий номер» (див. «Політика голосу в месенджерах»).

## Як воно працює (потік)

### Дзвінок
```
Клієнт → ТВІЙ номер (у Бінотел)
   ↓ Бінотел, правило за часом:
   ├─ ДЕНЬ → живі диспетчери
   └─ НІЧ  → SIP-переадресація → Vapi/Retell (Марія)
        ↓ real-time цикл (~0.6с):
        STT → LLM(OpenRouter, промпт Марії) → [CRM API] → TTS → клієнту
   ↓ webhook події → журнал звернень (ERP) — Марія знає, хто дзвонить
Кінець → транскрипт+статус → Журнал звернень (ERP); складне → "needs-you" → дайджест
```

### Повідомлення (TG/WA/IG/Viber)
```
Клієнт пише → webhook платформи → Hermes (потім n8n)
   → LLM(OpenRouter) + CRM API → відповідь через API платформи
   → запис у Журнал звернень (ERP) + статус
```

## Ключові контракти (інваріанти)

1. **Режим зміни:** активна лише в нічне вікно / між командами зміни. Телефон —
   правило роутингу Бінотел; месенджери — стан агента + cron-дублікат.
2. **Представлення:** завжди «Я нічний диспетчер Марія». Не людина, не наголошує AI.
   (⚠️ перевірити AI-disclosure для країн маршрутів.)
3. **Least-privilege CRM:** доступ лише до дозволених задач (розклад, місця, статус,
   заявка). Жодних фінансів, чужих персональних даних.
4. **Лог усього:** кожне звернення → Журнал звернень (модуль ERP), поля нижче.
5. **Строгий скоуп:** тільки whitelist дій (нижче). Без автономного «навчання» поза рамками.
6. **LLM-fallback:** OpenRouter обов'язково з резервною моделлю — нічний сервіс без нагляду.

## Журнал звернень (новий модуль ERP)

Замість сторонньої скриньки (Chatwoot) — **власний модуль у вашій ERP/CRM**, куди
Марія пише КОЖНЕ звернення. Вранці денний диспетчер працює звідси. Поля:

| Поле                        | Приклад                                                   |
| --------------------------- | --------------------------------------------------------- |
| Контакт                     | ім'я / телефон / @username                                |
| Канал                       | Телефон / Telegram / WhatsApp / …                         |
| Час                         | 2026-06-30 03:14 (Europe/Kyiv)                            |
| Що хотів (тема)             | «місця на Варшаву 05.07», «перенести квиток»              |
| Короткий зміст / транскрипт | текст або розшифровка дзвінка                             |
| Дія Марії                   | надала розклад / створила заявку №… / відклала            |
| **Статус**                  | ✅ вирішено · ⏸️ needs-you (потребує людини) · 🔁 в роботі |
| Прив'язка                   | до заявки/клієнта в CRM (якщо є)                          |

Ранковий дайджест = вибірка за ніч із цього журналу (насамперед `needs-you`).

## Guardrails — строгий план дій

### ✅ МОЖЕ
- Розклад, час/місце відправлення-прибуття, маршрути, пункти посадки
- Ціни зі сталого прайсу / CRM
- FAQ: багаж, документи, кордон, тварини, діти
- Перевірити місця / статус рейсу (CRM API)
- Прийняти/створити заявку (CRM API або лог)
- «Передам денному диспетчеру, відповість вранці»

### ⛔ НЕ МОЖЕ
- Гарантувати місце поза підтвердженням CRM
- Міняти ціни, знижки, домовлятись про оплату
- Приймати платежі
- Обіцяти повернення/компенсації
- Давати номер водія чи дані інших пасажирів
- Вирішувати спори/скарги/нестандартне

### ⏸️ ВІДКЛАДАЄ на денного диспетчера
- Повернення/обмін, скарги, спори, нестандарт → статус `needs-you` → дайджест

## Політика голосу в месенджерах

- **Голосові повідомлення (аудіо-нотатки)** — НЕ обробляються. Марія не робить STT
  з голосових у TG/WA/etc. (свідоме рішення).
- **Живий дзвінок у месенджері** (WhatsApp/Telegram/Viber call) — **скидати** і
  автоматично відписувати текстом:
  > «Для голосової розмови зателефонуйте, будь ласка, на робочий номер +XX».
  (Робочий номер = Бінотел → вночі Марія.)
- Уся жива розмова — **лише телефон** (єдиний голосовий канал: Бінотел → Vapi/Retell).
- Живі дзвінки в застосунках технічно не приймаємо; WhatsApp Business Calling API —
  не використовуємо (навіть якщо доступний).

## Дорожня карта

1. **Тиждень 0:** запити в Бінотел + CRM + ERP-модуль + Meta (паралельно, бо довгі).
2. **Тиждень 1:** VPS + **n8n-хаб** (HTTPS) + OpenRouter + Telethon-адаптер →

3. **Тиждень 1–2:** Журнал звернень (модуль ERP) + дайджест + команди зміни.
4. **Тиждень 2:** Vapi + Бінотел SIP → телефон уночі.
5. **Тижні 2–4 (після Meta):** WhatsApp (Coexistence) → Instagram. Viber — відкладено.
6. **Тиждень 4–5:** обкатка («тихий» тиждень) → go-live.

## Gotchas

- **Софт-агент не має лінії** — дзвінок дійде тільки через Бінотел/телефонію. На «голому» номері нічого не працює.
- **Бінотел → зовнішній SIP** — підтвердити в підтримці (спосіб 1 чи 2).
- **OpenRouter ≠ підписка ChatGPT** — потрібен API-баланс.
- **Автономія vs скоуп** — Hermes приборкати (learning-loop off); за тригером → n8n.
- **Журнал звернень** живе у ВАШІЙ ERP, не в сторонній скриньці — усі дані у вас.
- **AI-disclosure на дзвінках** — перевірити по країнах маршрутів.
- **TZ Europe/Kyiv** — зафіксувати скрізь (зміна/дайджест/роутинг).
