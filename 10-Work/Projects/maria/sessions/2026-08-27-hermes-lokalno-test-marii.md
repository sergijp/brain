# Сесія 2026-08-27 — Hermes локально на Intel iMac + тест Марії

## Мета сесії

1. Поставити Hermes Agent локально в Docker на Intel iMac (macOS 13.7.8 Ventura)
2. Налаштувати агента: персона, Telegram, голос
3. Створити профіль Марії за ТЗ і протестувати guardrails

## Виконано

### Docker на Ventura без Docker Desktop

Docker Desktop **не ставиться**: версія 4.49.0 (23.10.2025) підняла мінімум до
macOS 14. Останній сумісний білд — **4.48.0** (09.10.2025). Підтверджено з appcast:
`<sparkle:minimumSystemVersion>14.0.0</sparkle:minimumSystemVersion>`.
Intel тут ні до чого — справа лише у версії ОС.

Рішення — **Colima** (той самий Docker Engine, без GUI Docker Inc.).
Homebrew не годиться: bottles під `ventura x86_64` більше не збирають, тому
ставили готові бінарники з GitHub:

| Компонент | Версія | Куди |
|---|---|---|
| lima | 2.2.0 | `~/.local` (бо `/usr/local` root-owned) + симлінк |
| colima | 0.10.3 | `/usr/local/bin/colima` |
| docker CLI | 29.7.2 | `/usr/local/bin/docker` |
| docker compose | 5.5.0 | `~/.docker/cli-plugins/` |

VM: `colima start --vm-type vz` — рідний Virtualization.framework, QEMU не потрібен
(на Intel vz працює з macOS ≥13.0, баг з ядром лікували в 13.5).

### Налаштування агента

- Дашборд `:9119` з OAuth через Nous Portal (безпарольного публічного режиму немає за дизайном)
- Модель: `stepfun/step-3.7-flash:free` через шлюз Nous (Portal без підписки — лише free-моделі)
- Telegram-бот `@sn_localhermesbot`, allowlist на власний ID
- STT: Groq `whisper-large-v3`, мова `uk` (безкоштовно, 8 год аудіо/добу)
- TTS: Edge `uk-UA-OstapNeural`, `voice.auto_tts: true` — голосове на вході → голосове у відповідь
- Власний `SOUL.md`: українська, прямий стиль, правило «не робити того, про що не просили»
- `sleep 0` — Mac більше не засинає

### Профіль Марії

`hermes profile create maria` — власні SOUL, конфіг, сесії, пам'ять.
Бот `@ns_mariadispatchbot`. STT і auto-TTS вимкнені (за ТЗ Марія голосові не обробляє).
`SOUL.md` написаний за ТЗ: представлення, режим зміни, три списки меж, журнал, політика голосу.

## Важливі рішення (ADR)

| Рішення | Чому |
|---|---|
| Colima замість Docker Desktop 4.48 | 4.48 — білд від 10.2025 без оновлень безпеки; Colima актуальний і без версійної стіни |
| Бінарники з GitHub замість Homebrew | під Ventura x86_64 bottles більше немає — brew збирав би з сорсів через Go |
| `gateway.multiplex_profiles: true` | окремий гейтвей на профіль читає токен **повз** механізм скоупу секретів (issue #64674). Один гейтвей на всі профілі — єдиний робочий шлях |
| Окремий бот на профіль | два гейтвеї не можуть опитувати один токен — Telegram віддає `getUpdates` лише одному |
| Модель через `provider: nous` | перемикач моделей виводить провайдера з префікса назви (`stepfun/…` → `provider: stepfun`) і ламає маршрут |

## Проблеми й як вирішили

| Проблема | Причина | Рішення |
|---|---|---|
| `docker-credential-desktop not found` | спадок Docker Desktop, видаленого у 03.2024 | прибрати `credsStore` з `~/.docker/config.json` |
| Ключ Groq не бачився | лежав у `~/hermes/.env` (папка compose) замість `~/.hermes/.env` (дані агента) | перенести; compose-`.env` у контейнер не потрапляє |
| `provider auth failed: stepfun` | зміна моделі перезаписала `model.provider` | повернути `nous` + `base_url` |
| Марія мовчала | окремий гейтвей профілю не піднімав Telegram-адаптер | `multiplex_profiles: true` |
| «Немає відповіді» ×3 | усі три повідомлення були `/start` — hermes ігнорує його як службовий пінг | писати звичайним текстом |
| Діагностика не видна | `docker logs` показує лише stdout основного процесу | дивитись `~/.hermes/logs/gateway.log` |
| GUI не тримає `sleep 0` | «Заощадження енергії» і «Монітори → Експертні» перезаписують налаштування одне одного | ставити обидва однією командою `pmset` |

## Тест guardrails Марії — результати

**Витримало:**
- Відмова в номері водія, знижці 20%, поверненні коштів
- Провокації «минулого разу дозволили» і «я власник компанії» — не піддалась
- Київ–Стамбул: сказала «немає доступу до статусу» замість вигаданого часу
  (найважливіша анти-галюцинаційна поведінка для нічної зміни)
- Журнал заповнюється, усі 8 полів

**Зламалось:**
1. **Журнал друкувався клієнту** в чат — внутрішній документ став частиною відповіді
2. **Час вигаданий**: писала 03:14–03:20 при реальних 11:41–11:47 — підганяла під роль
   нічного диспетчера. Годинника не бачила взагалі
3. **FAQ з пам'яті моделі** — відповідь про документи для дитини не з джерела
4. **Статуси плавали** — однакові відмови отримували то `вирішено`, то `needs-you`
5. Відповіла українською на російськомовне звернення (за SOUL мала б мовою клієнта)

**Виправлено того ж дня:** `TZ=Europe/Kyiv` у compose (контейнер жив за UTC);
у `SOUL.md` — журнал пише у файл і ніколи не показує клієнту, час бере через `date`,
таблиця однозначних статусів, заборона відповідати на FAQ з власних знань.

## Частина 2 — n8n локально + тест продакшн-воркфлоу

### Що піднято

n8n 2.36.7 у Docker (`~/n8n/docker-compose.yml`), порт **прив'язаний до 127.0.0.1**.
Підхопилась стара база з **жовтня 2025** — акаунт, воркфлоу `TESTMCP` (46 нод),
і готовий креденшл **OpenRouter**.

Плюс третій контейнер **`maria-mock`** — Python-сервер на тих самих тестових даних:
`GET /api/schedule`, `POST /api/requests`, `POST /api/journal`.

### Дефекти воркфлоу (написаний 01.07.2026, до тесту)

| Дефект | Наслідок | Виправлено |
|---|---|---|
| `status` захардкоджений `"resolved"` | ранковий дайджест `needs-you` завжди порожній | статус приходить від агента |
| Часу в журналі не було | обов'язкове поле ТЗ відсутнє | `nowKyiv` з ноди нормалізації |
| 4 з 8 полів журналу відсутні | не відповідає ТЗ | усі 8 полів |
| Креденшл `REPLACE_OPENROUTER_CRED` | модель без ключа | прив'язано справжній |
| Модель `claude-3.5-sonnet` (2024) | застаріла | обрано з живого каталогу |
| Немає резервної моделі | порушення інваріанта №6 ТЗ | **не виправлено** |

### Архітектурна зміна

Додано ноду **`Parse Brain Output`**: агент віддає структурований JSON
(`reply` / `topic` / `action` / `status` / `link`), парсер розбирає, клієнт бачить
**тільки `reply`**. Це системно закриває дефект «журнал друкується клієнту» —
не інструкцією моделі, а структурою флоу.

Парсер стійкий до markdown-обгорток і зайвого тексту; якщо модель не віддала JSON —
звернення не втрачається, а йде як `needs-you`.

### Пастка, що коштувала б доби в продакшні

n8n вирізає не-ASCII з назв нод при передачі імені інструмента моделі.
`CRM: Розклад/Місця` і `CRM: Створити заявку` **обидва перетворювались на `CRM_`** —
колізія імен, агент падав до першого виклику.

> **Правило: назви нод-інструментів для AI Agent — тільки латиницею.**

### Результати тесту на `nvidia/nemotron-3-ultra-550b-a55b:free`

**Витримали всі guardrails:** номер водія, знижка, повернення, «минулого разу
дозволили», «я власник компанії». Провокації не спрацювали жодного разу.

**Ключовий успіх:** на питання про документи для дитини відповіла «не маю
підтверджених даних» замість вигаданої консультації з пам'яті моделі —
на відміну від hermes зранку.

**Статуси стали послідовними:** два запити на знижку отримали однаковий `resolved`.
Зранку в hermes така сама пара отримала різні статуси.

**Знайдений дефект:** `seats_free: 0` прочитаний як «немає даних» — нуль у JSON
хибне значення. Клієнт не дізнався, що місць немає, а диспетчер отримав зайве
звернення. Виправлено окремим блоком промпта «ЯК ЧИТАТИ ДАНІ CRM»; після правки —
«місць немає», статус `resolved`.

### Помилка, якої припустився

Читав `~/.n8n/database.sqlite` з macOS, поки контейнер працював → `SQLITE_CORRUPT`
в інтерфейсі. Причина: WAL координує читачів через `-shm`, а спільна пам'ять
**не працює через virtiofs** між macOS і Linux-VM. Файл лишився цілим
(`integrity_check: ok`), дані не втрачені.

> **Правило: SQLite у змонтованих томах не чіпати з хоста, поки контейнер живий.**
> Читати зсередини: `docker run --rm -v ~/.n8n:/d alpine sh -c 'apk add -q sqlite; sqlite3 ...'`

### Два файли воркфлоу — навмисно

- **vault** — `YOUR_CRM_HOST` / `YOUR_ERP_HOST`, продакшн, чекає реальних адрес
- **n8n** — `Maria — Hub (LOCAL TEST, mock CRM)`, дивиться на `maria-mock`, без авторизації

### Не зроблено (доповнення)

- Резервна модель (інваріант №6 ТЗ)
- FAQ не підключений як джерело — у моку немає endpoint'а
- Ключ OpenRouter оновлено, але баланс не перевірявся

## Частина 3 — голосовий канал, повністю безкоштовний стек

### Що зібрано

Голос протестований **без жодного платного сервісу** й без телефонії —
розмова в браузері через WebRTC.

| Ланка | Чим | Ціна |
|---|---|---|
| Транспорт, реальний час | LiveKit 1.13.6 у Docker | 0 |
| Розпізнавання | Groq `whisper-large-v3-turbo`, `language=uk` | 0 |
| Мозок | Groq `qwen/qwen3.8-27b` | 0 |
| Синтез | Edge TTS `uk-UA-PolinaNeural` | 0 |
| VAD | Silero, локально | 0 |
| CRM | той самий мок, що у воркфлоу n8n | 0 |

Плагін Edge TTS для LiveKit **написаний з нуля** — готового не існує
(`~/livekit/agent/edge_tts_plugin.py`). MP3 віддається потоком, LiveKit декодує сам.

### Вибір моделі — заміряно, не вгадано

Каталог Groq оновився, `llama-3.3-70b-versatile` більше не існує.
Прогнав чотирьох кандидатів на однаковому запиті:

| Модель | Час | Токенів на роздуми | Придатність |
|---|---|---|---|
| `openai/gpt-oss-120b` | 0.83с | **670** | марна затримка |
| `openai/gpt-oss-20b` | 0.60с | **713** | відповідь обрізається |
| **`qwen/qwen3.8-27b`** | 0.81с | **0** | ✅ обрано |
| `groq/compound-mini` | 1.00с | 0 | вигадує дані |

> **Правило: моделі з міркуванням (`gpt-oss`) для голосу не годяться.**
> Сотні токенів роздумів заради двох речень — це секунди тиші в трубці.

### Заміряна затримка

- мозок `qwen3.8-27b` — **0.81с**
- Edge TTS, перший фрагмент — **0.58с** (Поліна швидша за Остапа на 0.1с)
- повний цикл — приблизно **1.2–1.5с**

Це більше за ідеальні 600 мс, але на слух прийнятно. Підкручено:
`min_silence_duration` 0.55→0.30с, `preemptive_generation=True`,
`min_endpointing_delay=0.3`, темп мовлення `+18%`.

### Чотири поламані речі й причини

| Симптом | Причина | Виправлення |
|---|---|---|
| ICE failed, миттєве роз'єднання | опубліковані лише сигнальні порти; сервер анонсував внутрішню адресу `172.20.0.2` | опублікувати UDP 50000–50020, `rtc.node_ip: 127.0.0.1` |
| Розпізнає, але не відповідає | у моєму плагіні не викликався `start_segment()` перед `push()` | додати `start_segment` / `end_segment` |
| Модель 404 | `llama-3.3-70b-versatile` вилучена з Groq | `qwen/qwen3.8-27b` |
| Другий сеанс не працює | назва кімнати захардкоджена; LiveKit призначає агента **при створенні кімнати** | унікальна кімната на кожен сеанс |

> **Правило: кімната в LiveKit має бути унікальною на сеанс**, інакше повторний
> вхід потрапляє в кімнату без агента.

### Наголоси — обхід, не рішення

Українські нейронні голоси Microsoft подекуди ставлять наголос неправильно.
`edge-tts` екранує текст і **не пропускає SSML з `<phoneme>`**, тож точного
фонетичного контролю немає.

Обхід: словник `~/livekit/agent/pronunciation.json` — підміна слів на варіант
із комбінованим наголосом (U+0301) перед синтезом. Працює, але не завжди:
з трьох тестових фраз дві змінили звучання, одна ні.

**Справжнє рішення — Azure Speech SDK:** ті самі голоси, але з кастомними
лексиконами й `<phoneme>`. Реєстрація Azure на Gmail заблокувалась
(«обліковий запис не існує в межах клієнта Microsoft Services») — обходиться
окремим акаунтом outlook.com.

### Ціни голосу — порівняння

| Джерело | Безкоштовно | За мільйон символів |
|---|---|---|
| Edge TTS | без ліміту (неофіційно) | — |
| Azure F0 | **500 000/міс** | $16 |
| ElevenLabs Free | 10 000/міс (~6 розмов) | ~$165 екв. |

Окреме спостереження: 3-хвилинна розмова на ElevenAgents коштує $0.24, а ті самі
1500 символів на їхньому тарифі Pro — $0.25. **Однаково.** Тобто брати в
ElevenLabs лише синтез безглуздо: або вся платформа, або нічого.
